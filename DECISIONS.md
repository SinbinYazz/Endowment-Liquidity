# Decisions, checks, and limitations

Current-state review: October 30, 2026. This log describes the implemented model and the current scripts; earlier scenario examples are labeled separately from the UI defaults.

| Milestone | Decision or check | Reason / limitation |
|---|---|---|
| Scope | Focus on a fictional university endowment considering a new private commitment after a public-market decline. | One customer and decision keep the demo focused. Foundation payout law and multiple customer types are excluded. This log does not establish elapsed time against the assignment's three-hour target. |
| Evidence | Use primary sources from Kentucky, FIU Foundation, Rutgers, and NACUBO. | UK shows a real liquidity stress review; FIU gives a specific commitment approval rule. Neither proves annual-only analysis or a universal 60% policy. Rutgers explicitly requires ongoing liquidity reviews. |
| Sizing | Show a range based on 657 survey participants, an assumed 25–40% fit, and assumed $20–40k annual price. | Survey respondents are not the full market or necessarily buyers. |
| Commitment | Approval adds the full proposed amount to unfunded immediately. First-year new calls equal commitment × editable call rate. Deferral changes neither existing calls nor existing unfunded. | Constant monthly call timing is illustrative; actual schedules vary by fund. |
| Gate | Show current exposure before the proposal and pro forma exposure after it. Require approval only for a new commitment when current exposure exceeds the editable threshold; separately flag a proposal that would cross it. | Inspired by FIU's *current-exposure new-commitment approval* rule, not a prohibition on holding the portfolio. Deferral and a zero proposal request no approval. |
| Cash path | Calls transfer cash to private NAV and reduce unfunded; distributions transfer private NAV to cash without restoring unfunded. Spending leaves the portfolio. Stop portfolio projection at the first unmet cash need. | Drawing down the cash reserve means using marketable assets, not necessarily exhausting total liquidity. No later returns, gifts, fees, taxes, borrowing, notice periods, or marketable-asset transaction costs are modeled. The model cannot allocate an unmet need between calls and spending. |
| Secondary option | Enter sold NAV and transferred unfunded separately. Calls fall in proportion to unfunded transferred; distributions fall in proportion to NAV sold. Proceeds equal sold NAV less a discount. | User selected these labeled proportional assumptions. Transferred unfunded adds no cash. Actual timing and fund-specific cash flows remain unknown. |
| Downside headroom | Further decline is measured from the selected shocked public sleeve, with the proposal included. Display Already above gate or At gate as applicable. | This is a starting-exposure test; the monthly path remains separate. |
| Liquidity and spending | User selected initial liquid assets / scheduled year-one net needs, plus a no-distributions sensitivity. Default 3.0× floor constrains capacity. Annual spending is editable, default $20M / 5% of opening NAV. | These defaults are fictional. Coverage is not rolling coverage or forecast runway. Budget reductions require separate institutional consideration. Nonpositive net needs have no numeric coverage ratio. |
| Decision envelope | Check exposure at scenario start and every month-end, initial net-needs coverage against its floor, and cash funding; solve for the largest commitment satisfying all constraints. | A conditional 12-month planning limit, not approval or an optimal commitment. Default existing exposure already fails; zero capacity does not repair it. No later-year schedule is modeled. |
| Committee brief | Summarize the decision, approve-versus-defer deltas, remaining unfunded, and assumptions that change the envelope; provide a focused print view. Move sale sensitivity into an optional section. | Later threshold crossings indicate pacing pressure, not retroactive approval requirements. |
| Product AI | Use AI to build the prototype; use deterministic, calculation-backed text in the UI. | The assignment does not require in-product AI; deterministic text prevents invented numbers. |
| Delivery | Dependency-free static files; open locally or through GitHub Pages from `main` root. Node runs the separate calculation tests. | User enabled Pages. Prior releases were verified in the browser and matched hosted sources after line-ending normalization. No backend, account, or build step is needed. |
